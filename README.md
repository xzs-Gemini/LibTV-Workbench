# LibTV-Workbench｜LibTV 批量创作台

**在自己的电脑上打开一个中文网页，填写多条创作需求，让 LibTV 云端依次生成素材，并把结果下载到本机。**

适合需要批量探索画面、制作宣传素材或整理生成任务的个人创作者。你不必自己写调用脚本，但需要自己的 LibTV 账号及可用算力。生成由 LibTV 平台完成，不需要在本机安装 AI 模型或配备推理显卡。

这是基于 [Qiuxiangxiang/libtv-skill-pro](https://github.com/Qiuxiangxiang/libtv-skill-pro) 的社区二次开发，**不是 LibTV 官方产品**。当前发布的是 Windows 本地单用户源码版本，不是免安装软件，也不是多人在线平台。

> 状态：图片生成及下载已经真实验证。视频模型列表、参数和提交路径已接入，但视频端到端生成尚未验证通过。模型是否可用、账号权限与生成额度，以平台实际返回为准。

## 能用来做什么

| 需求 | 当前做法 |
| --- | --- |
| 给一个产品探索多种宣传画面 | 每行写一种场景，提交为一批任务 |
| 制作角色、场景、道具概念素材 | 使用页面示例，再修改主体、风格和构图 |
| 比较不同模型的结果 | 分别选择模型提交任务，集中预览和下载 |
| 管理多条生成需求 | 查看等待、生成、下载、完成和异常状态 |
| 保存结果及生成配置 | 自动按任务目录保存媒体和 `task.json` |
| 网络中断后检查结果 | 点击“核对云端状态”，查询并尝试下载已有结果 |

例如，为咖啡店写三条需求：“雨天窗边的咖啡杯”“清晨街角的咖啡店”“夜晚吧台上的拿铁”，可以按顺序生成三组候选素材。每条返回多少份结果取决于模型及数量设置。

当前没有参考图上传界面、自动配音、字幕、剪辑和成片拼接。它负责素材生成与任务管理，不会直接完成一条完整广告片。

## 它如何运作

一次生成经过以下步骤：

1. 浏览器把你填写的提示词、模型和参数发给本机 Python 服务。
2. 服务把任务保存到本地 SQLite 数据库，按顺序取出任务。
3. 服务调用 LibTV 官方 CLI，在你选择的云端项目中创建节点并开始生成。
4. CLI 使用你在本机完成的官方登录状态；实际计算发生在 LibTV 云端。
5. 工作台查询进度，生成成功后下载文件，并保存对应参数。

因此，**网页和队列在本机，生成在云端**。使用时必须联网，提交生成会使用当前登录账号的算力。页面不是 LibTV 官网的替代登录页。

## 与原项目的区别

上游本来就有批量生成、轮询、下载等脚本能力。本项目主要把这些操作整理成可直接点击的工作台，并补充任务恢复机制。

| 项目 | 上游脚本路径 | 新工作台路径 |
| --- | --- | --- |
| 操作入口 | 脚本、Agent Skill | 中文网页 |
| 调用与登录 | 旧 Access Key 接口 | 官方 CLI 1.0.2、官方网页登录 |
| 模型参数 | 脚本参数和模板 | 查询平台模型说明，展示部分常用参数 |
| 任务管理 | 按脚本执行 | SQLite 持久化队列、状态、取消排队、结果列表 |
| 异常处理 | 原脚本行为 | 未决任务先核对，不盲目重复提交生成 |

旧脚本保留在 `scripts/`。旧版安装与使用说明见 [UPSTREAM_README.md](UPSTREAM_README.md)，其中指向上游的安装命令不会安装本工作台。

## 安装与首次启动

以下命令用于 **Windows x64 + PowerShell**。已验证 Python 3.12 和官方 CLI 1.0.2。其他系统或 CLI 版本尚未逐一验证。请逐段执行；任何一步报错时先处理错误，再继续。

### 1. 准备 Git 和 Python

先安装 Git 与 Python 3.12。安装后新开 PowerShell，确认：

```powershell
git --version
py -3.12 --version
```

若 `py` 不存在，但 `python --version` 显示 Python 3.12，可将下方创建环境的 `py -3.12` 换成 `python`。

### 2. 下载本项目并创建环境

在准备存放项目的文件夹中打开 PowerShell：

```powershell
git clone https://github.com/xzs-Gemini/LibTV-Workbench.git
cd LibTV-Workbench
py -3.12 -m venv .venv
```

新工作台只使用 Python 标准库，不需要额外执行 `pip install`，也不需要激活虚拟环境。

### 3. 下载官方 CLI 1.0.2

以下是官方静态文件服务上的 Windows x64 下载地址，2026-10-11 检查可访问。文件只下载到被 Git 忽略的 `.tools/`，不是本仓库重新分发的二进制。

```powershell
New-Item -ItemType Directory -Force .tools | Out-Null
Invoke-WebRequest -UseBasicParsing -Uri 'https://liblibai-web-static.liblib.cloud/cli/1.0.2/libtv-windows-amd64.zip' -OutFile .tools/libtv-1.0.2.zip
Expand-Archive -LiteralPath .tools/libtv-1.0.2.zip -DestinationPath .tools/libtv-1.0.2
$env:LIBTV_CLI = (Resolve-Path .tools/libtv-1.0.2/libtv-win-x64/libtv.exe).Path
& $env:LIBTV_CLI --version
```

预期版本为 `1.0.2`。这是首次安装命令；已存在相同解压目录时无需重复解压。如果下载地址失效，请从 LibTV 官方渠道获取兼容版本，不能用同名但接口不同的第三方 CLI 替换。

已经安装 CLI 的用户可跳过下载，将 `LIBTV_CLI` 设置为实际 `libtv.exe` 路径；设置后从同一个 PowerShell 启动工作台。按以上默认目录安装时，后续双击启动无需再次设置变量。

### 4. 登录自己的账号

```powershell
& $env:LIBTV_CLI login web --open
```

在打开的官方网页完成登录，等待命令返回成功。**不要把账号密码、验证码或登录文件发给本项目维护者。** 官方 CLI 会在当前系统用户目录保存登录凭据。

检查是否已有可用项目：

```powershell
& $env:LIBTV_CLI project list
```

若没有项目，可在官方页面创建，或显式执行以下命令创建一个空白画布项目：

```powershell
& $env:LIBTV_CLI project create '我的素材工作台'
```

### 5. 启动网页

```powershell
./Start-Workbench.ps1
```

也可以双击项目目录中的 `Start-Workbench.cmd`。浏览器打开本机地址 `http://127.0.0.1:5212`。若浏览器打开得比服务快，等待几秒后重新加载页面。

成功的标志：页面显示“本地服务已连接”，能够选到自己的项目和平台返回的模型。仅显示本地服务已连接，不代表账号一定登录成功；项目或模型加载错误还需要检查 CLI 登录和网络。

如果 PowerShell 提示禁止运行脚本，可直接以前台方式运行，无需修改系统执行策略：

```powershell
./.venv/Scripts/python.exe -m workbench.server --open
```

前台方式需要保持终端打开，按 `Ctrl+C` 停止。不要同时启动两个实例。

## 使用方法

### 第一次生成图片

1. 在“保存到 LibTV 项目”中选择刚才创建或已有的项目。
2. “素材类型”选“图片”，选择平台当前提供的图片模型。
3. 设置页面显示的比例、分辨率、数量等选项；可用选项随模型变化。
4. 在“创作需求”中先填写一条简单描述，例如：

```text
游戏道具概念图，一盏黄铜手提灯，暖色光，居中构图，白色背景，无文字
```

5. 点击“加入队列并开始生成”。此操作会实际提交生成并使用账号额度。
6. 在右侧查看状态，完成后点击缩略图或下载链接保存文件。

### 批量生成

每个非空行对应一个任务，每批 1–20 条；同一批任务使用相同的项目、模型和参数，按顺序执行。需要不同参数时分批提交。

```text
一盏黄铜手提灯，游戏道具概念图，白色背景
一柄银色长剑，蓝色宝石，游戏道具概念图，白色背景
一个皮革旅行背包，游戏道具概念图，白色背景
```

### 高级参数与视频

“高级参数”接受 JSON 对象，例如 `{ "seed": 42 }`；只有所选模型支持时才有效。页面同时显示平台返回的参数说明。表单中已经展示的同名参数会覆盖 JSON 中的值，不能通过这里修改模型名或提示词。

视频的操作入口相同：选择“视频”、模型及平台提供的时长等参数，再提交描述。但**目前没有视频真实生成成功的验证记录**，也没有在此界面上传首尾帧或参考素材的功能，不能据此认为所有视频模型都能直接使用。

## 任务状态与异常恢复

| 页面状态/操作 | 含义与处理 |
| --- | --- |
| 等待中 | 尚未提交，可点击“取消排队” |
| 创建云端任务／准备生成／生成中 | 已进入云端调用阶段，不提供云端取消按钮 |
| 下载中 | 云端生成结束，正在把结果保存到本机 |
| 已完成 | 文件已保存，可下载；“重新下载”只获取已有结果 |
| 需要核对 | 远端是否成功暂不确定；点击“核对云端状态”查询，不会重新运行生成 |
| 算力不足 | 本地队列暂停；处理额度后点击“额度已处理，继续排队任务” |

继续队列只恢复尚未提交的任务。已经因算力不足失败的需求需要重新填写提交；先确认原任务状态，不要连续点击创建重复任务。重启后不确定是否已提交成功的任务也会要求核对。

关闭浏览器不会停止后台服务，后台仍可能继续提交排队任务。希望停止新增生成时，先取消未提交的排队任务。停止本地进程不能保证取消已被平台接受的云端生成。

启动脚本采用隐藏后台进程，目前没有图形化“关闭后台”按钮。需要手动控制生命周期时，使用上面的前台启动方式；已有后台时，先在任务管理器中确认属于本项目的 Python 命令行，再结束对应进程，不要结束所有 Python 进程。

## 账号与数据

- 新工作台不要求手动填写 API Key，使用官方 CLI 当前登录账号。
- 每个人在自己的电脑安装并登录，就使用各自的账号和额度。
- 多人共用同一个后台，会共用其登录账号、任务记录和额度；本项目没有网站账号、权限及用户数据隔离。
- 服务仅监听本机。`127.0.0.1` 指访问者自己的电脑，把这个地址发给别人不能让别人访问你的工作台。
- 切换 CLI 账号不会自动清空或隔离本地历史；当前按单个系统用户、单个实例使用。

| 本地位置 | 内容 |
| --- | --- |
| `data/tasks.sqlite3` | 任务及状态数据库 |
| `data/outputs/<任务ID>/` | 下载的媒体及 `task.json` 参数记录 |
| `data/server.log`、`data/server-error.log` | 启动脚本运行日志 |
| 当前系统用户目录下的 `.libtv/` | 官方 CLI 管理的登录及配置文件 |

备份任务时先停止本地服务，再备份 `data/`。不要分享登录目录、密码、验证码或完整日志中的敏感信息。仓库不包含账号、生成记录、CLI 二进制及虚拟环境。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 找不到 Python | 检查 Python 3.12 安装，重新创建 `.venv`；也可用 `LIBTV_PYTHON` 指定可执行文件 |
| 找不到 `libtv.exe` | 检查下载和解压路径，或设置 `LIBTV_CLI` 后在同一终端启动 |
| 项目为空／登录过期 | 用同一 CLI 重新完成官方登录，运行 `project list` 检查，之后重新加载整页 |
| 模型参数报错 | 先移除高级 JSON 参数，核对所选模型说明；不要混用别的模型的选项 |
| 页面“刷新”后仍没有新项目 | 此按钮主要刷新任务状态；项目或模型配置变化后重新加载整页 |
| 一直显示需要核对 | 检查网络和官方画布状态，稍后再次核对；工作台不会自动重复生成 |
| 下载失败 | 保留任务，网络恢复后核对或重新下载；不要为下载失败重新生成 |
| 双击后没有页面 | 在 PowerShell 前台启动以查看错误，检查 5212 端口和 `data/server-error.log` |

## 开发与验证

| 文件 | 作用 |
| --- | --- |
| `workbench/core.py` | 官方 CLI 适配、SQLite 队列、状态核对和下载 |
| `workbench/server.py` | 本机 HTTP 接口与文件服务 |
| `workbench/web/` | 中文网页、模型表单及任务列表 |
| `workbench/import_node.py` | 开发用的已有云端节点结果导入工具 |
| `tests/test_workbench.py` | 离线队列测试 |
| `scripts/` | 保留的上游旧脚本 |

环境变量：`LIBTV_CLI` 指定 CLI；`LIBTV_PYTHON` 指定启动脚本使用的 Python；`LIBTV_PROJECT` 指定默认选中的项目 ID。CLI 查找顺序是显式配置、本仓库默认 `.tools/` 路径、系统 PATH。

离线测试不调用真实平台、不消耗算力：

```powershell
./.venv/Scripts/python.exe -m unittest discover -s tests -p test_workbench.py -v
```

2026-10-11 验证：8 项离线测试通过；真实登录、项目/模型查询、Z-image Turbo 图片生成和下载通过。之后的生成遇到平台算力不足，验证了队列暂停。视频生成和其他电脑从零安装尚未完成端到端验证。

二次开发可从参考图上传、业务提示词模板、素材分类导出入手；多人部署需要另外开发账号、授权及任务隔离，不能只修改监听地址。新增功能应继续区分“读取状态”和“提交生成”，避免错误恢复导致重复消耗额度。
